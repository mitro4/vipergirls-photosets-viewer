# ViperGirls Photo Sets Viewer

Просмотр фотосетов с форума viper.to в чистом и быстром десктопном или веб-интерфейсе:
крупные обложки, карусель с предпросмотром при наведении, полноэкранный лайтбокс
со слайд-шоу, постоянная очередь загрузок (папки по тредам на десктопе, стриминг
ZIP в вебе), история лайков и загрузок, нумерованная пагинация, живой поиск по
форуму и поддержка SOCKS5/HTTP-прокси для доступа при блокировках со стороны
провайдера.

Работает тремя способами:

| Режим | Для чего лучше всего | Требования |
|---|---|---|
| **Десктопное приложение** (Windows `.exe`, Linux `.deb`/`.rpm`/`.AppImage`) | Конечные пользователи — не требуется технических навыков | Просто скачать и запустить |
| **Docker** | Самохостинг на сервере/NAS | Docker |
| **Режим разработки** | Контрибьюторы | Python 3.12 + Node.js 20 |

## Возможности

- **Десктопный GUI** — нативное окно (Electron/Chromium) со встроенным Python
  бэкендом. Никакого браузера, Docker или терминала — просто двойной клик по
  приложению.
- **Навигация по категориям** — все разделы Photo Sets (Softcore, Hardcore, Fetish,
  Lesbian, Transsexual, Gay и т. д.) в боковой панели, с кнопкой **Назад** в
  шапке для возврата из треда. Навигация с keep-alive возвращает в галерею
  мгновенно (без перезагрузки, позиция прокрутки сохраняется).
- **Волновая прогрессивная загрузка** — карточки загружаются согласованными
  волнами: сначала все миниатюры обложек во всех карточках, затем предпросмотры,
  затем каждая карточка по одной картинке повышает качество до среднего. Плавное
  переключение (вспышка яркости) — без пустых вспышек или «битых» значков.
- **Предпросмотр при наведении** — перемещение мыши над обложкой перебирает первые
  5 фотографий набора (карусель с 5-зонным кроссфейдом и индикатором прогресса).
- **Полноценный просмотрщик фотосетов** — сетка миниатюр (пагинация по 12
  изображений на страницу, сгруппированы по постам) + полноэкранный лайтбокс с
  управлением с клавиатуры, зумом, свайпами, скачиванием отдельных изображений,
  предзагрузкой соседних кадров (±1) и переключателем слайд-шоу Play/Pause с
  настраиваемым интервалом 1–5 секунд.
- **Очередь загрузок** — постоянная очередь (переживает перезапуск приложения)
  заменяет старое всплывающее окно загрузки. Кнопка на панели инструментов с
  бейджем активных задач открывает панель очереди: каждая строка показывает
  заголовок треда, статус и прогресс `[загружено/всего]`, с управлением
  СТОП/СТАРТ по каждой строке и кнопкой очистки очереди. Треды скачиваются
  параллельно до `thread_concurrency`, в порядке очереди. Кнопка скачивания в
  правом верхнем углу карточки добавляет тред в очередь. В десктопном
  приложении каждый фотосет сохраняется в собственную папку (имя — по треду,
  жёстко связан с кэшем, чтобы не тратить диск дважды); в режиме Docker/веб
  вместо этого стримится ZIP. Промежуточные страницы хостов (interstitials)
  разрешаются «на лету» и кэшируются. Неудачные изображения можно повторить.
- **Лайки** — нажмите на сердечко на любой карточке, чтобы лайкнуть тред на форуме
  (через механизм «thanks» в vBulletin). Отдельная вкладка **Liked** показывает
  все лайкнутые вами треды — с той же сеткой, выделением и пакетным скачиванием.
- **История загрузок** — вкладка **Downloads** показывает все сохранённые вами
  треды с действием «Открыть папку» (десктоп), которое показывает её в файловом
  менеджере. Записи об удалённых папках очищаются автоматически.
- **Постоянная авторизация** — ваша сессия на форуме сохраняется между
  перезапусками, поэтому вы остаётесь залогинены.
- **Нумерованная пагинация** — элементы «первая / предыдущая / окно страниц /
  следующая / последняя» на каждом списке (категории, поиск, тред),
  дублируются сверху и снизу.
- **Сетевой прокси** — поддержка SOCKS5/SOCKS5h/HTTP-прокси (с необязательной
  аутентификацией) для случаев, когда провайдер блокирует форум или
  изображений-хосты. Включение/выключение без потери сохранённых учётных данных.
  Применяется и к парсингу форума, и к загрузке изображений.
- **Вход на форум** — необязательная аутентификация vBulletin для тредов,
  доступных только участникам.
- **Поиск** — живой поиск по форуму (vBulletin Advanced Search), ограниченный
  любой комбинацией разделов, с пагинацией, подгрузкой кэшированных обложек и
  сортировкой результатов по дате поста.
- **16 изображений-хостов** — imx.to, imgbox, pixhost, imagevenue, imagetwist,
  acidimg, imagebam, pimpandhost, postimg, turboimagehost, vipr.im и другие.
  Промежуточные страницы разрешаются «на лету» и кэшируются. Матчер `pixhost`
  покрывает оба зеркала — `.to` и `.cc` (чистое преобразование URL, без DNS).
  Если полноразмерное изображение недоступно (например, turboimagehost или
  imx.to за challenge), отдаётся кэшированная миниатюра как запасной вариант.
  Анимация GIF сохраняется.
- **Дисковый кэш** — разрешённые изображения кэшируются без ограничения
  размера. В Settings отображается текущий размер кэша и кнопка очистки.
  Ограничения параллелизма по каждому хосту не дают одному медленному хосту
  тормозить остальные. Автоматический выключатель (circuit breaker) помечает
  «мёртвые» хосты для мгновенного 502 вместо тайм-аута.
- **Настраиваемый параллелизм** — `download_concurrency` (общий бюджет на
  интерактивный просмотр + ZIP-загрузки + фоновый предзагруз) и
  `thread_concurrency` (пакетные обложки, параллельные воркеры очереди,
  многопоточные ZIP). Меняется на лету.

## Быстрый старт

### Десктопное приложение (рекомендуется большинству пользователей)

Скачайте последний релиз для вашей ОС:

- **Windows**: `vipergirls-viewer-*-win-x64-setup.exe` (установщик) или
  `*-portable.zip` (без установки — просто распакуйте и запустите)
- **Linux**: `.deb` (Debian/Ubuntu), `.rpm` (Fedora/openSUSE) или
  `.AppImage` (любой дистрибутив, per-user, без установки)

Запустите приложение — откроется нативное окно, стартует встроенный бэкенд, и вы
уже работаете. Данные хранятся в профиле пользователя (`%APPDATA%` на Windows,
`~/.local/share` на Linux).

### Docker

```bash
cp .env.example .env        # опционально: добавьте учётные данные форума для наборов только для участников
docker compose up -d --build
```

Откройте **http://localhost:8888**.

### Разработка

```bash
# Бэкенд
cd backend && pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000

# Фронтенд (проксирует /api → :8000)
cd frontend && npm install && npm run dev
```

## Сборка пакетов из исходников

Все пакеты собираются воспроизводимо в Docker — **локальный инструментарий не нужен**
(нужен только Docker на Linux-хосте). Скрипты сборки лежат в `packaging/scripts/`.

### Linux (deb / rpm / AppImage)

```bash
./packaging/scripts/build-deb.sh        # → dist-packages/*.deb
./packaging/scripts/build-rpm.sh        # → dist-packages/*.rpm
./packaging/scripts/build-appimage.sh   # → dist-packages/*.AppImage

# Все три сразу:
./packaging/scripts/build-all.sh
```

Каждый пакет включает автономный runtime Python 3.12 + Electron (Chromium).
Пакеты deb/rpm устанавливают файл `.desktop`, службу systemd (серверный режим на
`:8000`) и хранилище данных в профиле пользователя. AppImage — единый портативный
файл.

### Windows (портативный ZIP + NSIS-установщик)

Кросс-компилируется из Linux — **Wine или Windows-хост не требуются**:

```bash
./packaging/scripts/build-windows.sh    # → dist-packages/*-win-x64-*
```

Результат:
- `*-win-x64-portable.zip` (~137 MB) — распакуйте и запустите `electron\electron.exe`
- `*-win-x64-setup.exe` (~98 MB) — NSIS-установщик со значками в меню «Пуск» и на
  рабочем столе и деинсталлятором

Использует встраиваемый Python 3.12 для Windows (у всех зависимостей есть готовые
wheels для win_amd64) и Electron для Windows.

### Docker-образ

```bash
docker compose up -d --build   # собирает и запускает весь стек
```

Подробности архитектуры сборки см. в `PACKAGING.md`, документацию для
разработчиков — в `AGENTS.md`.

## Конфигурация

### Переменные окружения (`.env`)

| Variable | Default | Description |
|---|---|---|
| `VIPER_USERNAME` | _(empty)_ | Имя пользователя на форуме (необязательно) |
| `VIPER_PASSWORD_MD5` | _(empty)_ | MD5 от пароля форума (необязательно) |
| `VIPER_REQUEST_LIMIT` | `2` | Макс. запросов/сек к форуму |
| `VIPER_DOWNLOAD_CONCURRENCY` | `8` | Сид первого запуска для runtime-настройки `download_concurrency` |
| `VIPER_THREAD_CONCURRENCY` | `2` | Сид первого запуска для `thread_concurrency` |
| `VIPER_DOWNLOAD_TIMEOUT` | `30` | Сид первого запуска для `download_timeout` (сек) |
| `VIPER_MAX_RETRIES` | `3` | Сид первого запуска для `max_retries` |
| `VIPER_CACHE_LIMIT_GB` | `0` | Сид первого запуска для лимита LRU-очистки кэша, ГБ (0 = без лимита) |

Сид-переменные применяются **один раз** — когда ключа ещё нет в таблице
настроек (первый запуск). После этого побеждает значение из UI приложения, а
переменная окружения игнорируется. Docker Compose прокидывает весь файл `.env`
в контейнер автоматически.

### Настройки во время выполнения (в приложении)

Редактируются в диалоге Settings, хранятся в SQLite (`GET/PUT /api/settings`):

- **Proxy** — `socks5://`, `socks5h://`, `http://` с необязательными
  `proxy_username`/`proxy_password`. Включение/выключение через `proxy_enabled`
  без потери сохранённых учётных данных. Применяется и к парсингу форума, и к
  изображениям-хостам.
- **Concurrency** — `download_concurrency` (общий: просмотр + ZIP + предзагруз),
  `thread_concurrency` (пакетные обложки + многопоточный ZIP).
- **Зеркало форума** — переключение между известными зеркалами форума
  (planetviper.club, viperbb.rocks, viperkats.eu и т. д.) на лету.
- **Download** — `order_images` (последовательные имена файлов),
  `download_timeout`, `max_retries`, а также два переключателя:
  **автоскачивание при добавлении в очередь** (по умолчанию вкл.) и
  **автоочистка по завершении треда** (по умолчанию выкл.).
- **Кэш** — опциональный лимит размера (`cache_limit_gb`, 0 = без лимита): при
  заданном лимите фоновая задача раз в 30 минут чистит дисковый кэш картинок по
  LRU. В Settings отображается текущий размер кэша и кнопка очистки
  (`POST /api/cache/clear`).
- **Папка загрузок** — куда сохраняются папки с изображениями по тредам (только
  десктоп; выбирается через системный диалог и сохраняется между перезапусками).

## Архитектура

- **Бэкенд** — Python / FastAPI. Парсит через `viper.click/vr.php` (чистый XML)
  с прямым фолбэком на `viper.to` через `curl_cffi` (обход Cloudflare).
  Разрешает 16 inline-хостов изображений и стримит ZIP по запросу.
  Ограничение скорости к форуму (token bucket, по умолчанию 2 req/s). SQLite для
  кэширования (треды, изображения, разрешённые URL, настройки).
- **Фронтенд** — React + TypeScript + Vite + TailwindCSS. TanStack Query для
  выборки данных, волновая прогрессивная загрузка изображений, навигация по
  категориям с keep-alive, 5-зонная карусель при наведении, лайтбокс с
  управлением с клавиатуры/касаниями и предзагрузкой ±1, виртуализация через
  react-window для больших сеток.
- **Десктоп** — главный процесс Electron запускает Python-бэкенд как дочерний
  процесс, ждёт `/api/health`, открывает BrowserWindow на Chromium. Preload-мост
  открывает IPC для open-folder / choose-folder, а загрузки автоматически
  сохраняются в настраиваемую папку. Бэкенд переиспользуется, если уже запущен
  (например, через systemd). F12 открывает DevTools.
- **Контейнер** — многоэтапная сборка Docker: Node собирает SPA, затем Python-образ
  запускает uvicorn (API) за Caddy (статические файлы + обратный прокси).
